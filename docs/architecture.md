# ESG Multimodal Extraction Agent Architecture

## Current Version

This document describes the current v1.1 token-safe baseline architecture.

The project currently uses a dual-route extraction workflow:

1. Route A extracts quantitative ESG indicators from appendix performance tables.
2. Unified Route B builds one reusable RAG corpus/index, extracts qualitative
   ESG mechanism indicators, and runs quantitative fusion over Route A fields.
3. Merge Pipeline combines both routes into a unified Core ESG result.

The current system is stable as a v1.1 baseline, but it is not yet a full Agent Harness architecture. The planned v1.2 upgrade should organize the existing routes under a higher-level harness without changing the core extraction logic.

## Route A: Appendix Table Extraction

Route A is implemented by `pipeline.appendix_pipeline.ESGAppendixPipeline`.

It runs the following agents in order:

1. `AppendixSnifferAgent`
   - Finds ESG appendix or performance table candidate pages in the PDF.
   - Writes appendix detection state such as `appendix_found` and `candidate_pages`.

2. `PageRenderAgent`
   - Renders selected PDF pages into page images.
   - Produces image artifacts used by the table OCR step.

3. `VLMTableOCRAgent`
   - Sends page images to the VLM table OCR utility.
   - Extracts all detected table rows without deciding whether a row is a Core ESG metric.
   - Saves `all_table_rows.json`.

4. `SchemaMatchAgent`
   - Matches extracted table rows to the Core ESG schema.
   - Uses heuristic rules, alias matching, optional LLM fallback, and schema validation.
   - In the v1.1 stable baseline, large reruns should use `LLM_MATCHER_ENABLED=false`.
   - Produces `standard_esg_results.json` and `unknown_metrics.json`.

5. `ValidationAgent`
   - Summarizes extraction quality and coverage.

Route A exports:

- `standard_esg_results.csv`
- `standard_esg_results.json`
- `unknown_metrics.csv`
- `unknown_metrics.json`
- `pipeline_state.json`
- intermediate artifacts such as page images and `all_table_rows.json`

## Route B: Unified RAG Extraction

Route B is implemented by `pipeline.text_pipeline.ESGTextPipeline`.
It performs PDF ingest and shared index construction once, then runs two
internally separate extraction stages:

1. qualitative text extraction;
2. quantitative fusion for Route A quantitative fields.

Quantitative fusion retrieves evidence for every Route A quantitative field
from the shared text and structured-table index. It calls the quantitative LLM
only when Route A is missing, low confidence, zero-valued, or has a conflicting
structured candidate. High-confidence Route A values without conflict are
retrieved for verification without spending an LLM call.

It targets Core ESG fields whose schema entry uses:

```text
preferred_source == "main_text_rag"
```

The Route B flow is:

1. Extract PDF text by page.
2. Check whether the PDF has enough usable text layer.
3. Save `route_b_text_pages.json`.
4. Chunk page text when text is available.
5. Retrieve relevant chunks for each target qualitative field.
6. Use the LLM text extractor to identify values, summaries, evidence, source pages, and confidence.
7. Save Route B result files.

Route B exports:

- `route_b_text_pages.json`
- `route_b_chunks.json`
- `route_b_text_results.json`
- `route_b_text_results.csv`
- `route_b_summary.json`
- `route_b_combined_chunks.json`
- `route_b_quant_results.json`
- `route_b_quant_results.csv`
- `route_b_quant_summary.json`

Legacy `route_b2_*` artifacts are ignored and are no longer generated by the
unified Route B pipeline.

When a report has no usable text layer, Route B records missing results with the reason `no_text_layer_or_too_little_text`.

## Merge Pipeline

The merge step is implemented by `pipeline.merge_pipeline.ESGMergePipeline`.

It reads per-report outputs:

- Route A: `standard_esg_results.csv`
- Route B: `route_b_text_results.csv`

The merge rule is conservative:

1. Normalize Route A rows into the merged output format.
2. Keep Route A extracted values as the primary result.
3. Use Route B as supplementary evidence when Route A already extracted the field.
4. Fill a final missing field from Route B only when:
   - Route A is missing for that field.
   - Route B is matched.
   - Route B confidence is at least the configured threshold, currently `0.5`.

Merge exports:

- `merged_esg_results.csv`
- `merged_esg_results.json`
- `merge_summary.json`

Batch merge is run through:

```bash
python -m scripts.run_merge_batch
```

## Current Limitations

The current v1.1 baseline is stable, but several architectural limitations remain:

- Route A, Route B, merge, and analysis are connected mainly by scripts and file naming conventions.
- There is no single top-level Agent Harness that owns run planning, route dispatch, artifact contracts, recovery, and evaluation.
- Route A has an agent chain, but Route B and Merge Pipeline are pipeline classes rather than harness-managed agents.
- Cross-route state is stored on disk instead of in a unified run manifest.
- Large-scale schema reruns should keep `LLM_MATCHER_ENABLED=false` to avoid unstable or expensive LLM fallback behavior.
- Some existing source comments and strings display encoding artifacts, although the current behavior can still be documented and operated.
- `output/` contains run artifacts and should not be treated as source-of-truth application code.

## Planned v1.2 Agent Harness Upgrade

The v1.2 upgrade should organize the existing stable extraction logic under a new harness layer.

The harness should add orchestration without rewriting the current extraction internals:

1. Define a top-level run manifest
   - Report identity
   - Route status
   - Artifact paths
   - Configuration snapshot
   - Error summary

2. Define route-level contracts
   - Route A input and output artifacts
   - Route B input and output artifacts
   - Merge input and output artifacts
   - Evaluation input and output artifacts

3. Add a route registry
   - `route_a_appendix_table`
   - `route_b_text_rag`
   - `merge`
   - `evaluation`

4. Add resumable execution
   - Skip completed steps when valid artifacts already exist.
   - Re-run specific routes without deleting unrelated output.
   - Preserve failed-step diagnostics.

5. Keep current core logic stable
   - Do not rewrite schema matching.
   - Do not rewrite VLM table extraction.
   - Do not rewrite Route B LLM extraction.
   - Wrap the existing pipeline classes and scripts behind a cleaner orchestration interface.

The goal of v1.2 is therefore architectural organization, reproducibility, and easier batch operation, not a change in extraction semantics.
